第20回 機能を足すときの手順

ここまでで、走行体のプログラムを読んで、動かして、ログを読めるようになりました。この回は、自分でプログラムを直したり、機能を足したりするときの手順をやります。2026年10月に実際に「ボトルデリバリー → ET相撲」の走りを足したときに、どのファイルをどの順で触ったかを追いながら進めます。

用意するもの：これまでのPC

説明

進め方

チームでは、次の順で進めることにしています。

資料を読む → モデルで考える → 設計 → 作る → ビルド → シミュレータ → 実機 → ログを読む → 直す

うまくいかなければ、前に戻ります。いちばん大事なのは、プログラムを先に書き始めないことです。少なくとも、何をするか（道順）、どんな状態があって何で切り替わるか（状態機械図、メモでもいい）、失敗したらどうするか（見つからない、見失った、時間切れ）の3つは、先に決めます。

ボトルの走りを足したときの順番

2026年10月に、LAPのあと「ボトルを運ぶ → ET相撲 → ガレージ」と走るオプション（--bottles）を足しました。そのときの順番です。

  1. 規約とコースの図を読んで、ボトルの置き場、ゾーン、土俵の位置を表にした（docs/設計/ボトル難所攻略設計.md）
  2. 道順と、失敗したときの動きを決めた（同じファイル）
  3. 距離や速さの数字に名前を付けた（config/parameters.h）
  4. 起動オプションを足した（src/app_options.h、src/app_options.c、src/main.c）
  5. オプションのテストを書いた（test/test_app_options.c）
  6. 手順の本体を新しいファイルに書いた（src/app_bottles.c、src/app_bottles.h）
  7. ビルドの一覧に足した（Makefile）
  8. 本体の入口から呼んだ（src/app.c）
  9. シミュレータにボトルを置いて300回走らせて、失敗を1つずつ直した（test/simulator/bottle_world.c）
  10. 決めたことを記録した（docs/設計/判断記録.md）

最初は成功率0％でしたが、9の「失敗を1回ずつ見て直す」をくり返して、300回中299回まで上がりました。曲線のつなぎ目、青い区間、角、ゾーンの近さ…と、毎回違う原因でした。

数字を変えるとき

config/parameters.h で名前を探して（Ctrl + Shift + F）、値を変えます。そのとき、コメントに「いつ、なぜ、何を見て」変えたかを書きます。

#define RALLY_LAP_TO_GARAGE_MM   1020   /* [実機 2026-10-02] LAPの青線を見つけてから、ガレージの中で止まるまで。
                                           1100ではガレージの奥寄りに止まったので減らした */

parameters.h を変えたら、必ずラズパイに送り直してビルドし直します。

書き方の決まり

チームのプログラムは、次の決まりで書いています（CLAUDE.md にも書いてあります）。

main は始める準備だけにして、中身は役割ごとのファイルに分けます。数字は config/parameters.h に名前を付けて置きます。機械にさわる部分（src/device/）は分けておきます。テストとシミュレータで偽物に差し替えられるようにするためです。

ログには判断の理由を出します（「◯◯なので△△します」）。実機でうまくいかなかったとき、ログだけで原因が追えるようにするためです。コメントは日本語で「なぜ」を書きます。実機で分かったことには日付を付けます。警告は1つも出ないようにします。

記録を残す

決めたことは docs/設計/判断記録.md に、日付、決めたこと、理由、影響を書きます。変更は「何を、なぜ」を書いてコミットします。

なぜそうしたかが残っていないプログラムは、来年だれも直せません。

手順

この回は、オプションを1つ足してみます。走行体の動きには関係しない、練習用のオプションです。

  1. 練習用のブランチを作る（git switch -c practice-自分の名前のローマ字）
  2. src/app_options.h の構造体に int hello; を足す
  3. src/app_options.c で、初期値を0にして、--hello が来たら1にする（--from-main の書き方をまねする）
  4. src/main.c の --help の説明に1行足す
  5. test/test_app_options.c に、--hello を渡したら hello が1になるテストを足す
  6. sh scripts/local_test.sh で全部 OK になるか確かめる
  7. git diff で変えた所を見直す
  8. 終わったら、元のブランチに戻ってブランチを消す（先輩と一緒に）

演習

演習20-1　オプションを足す

手順どおりに --hello を足して、テストが通るところまでやってください。

演習20-2　設計から考える

シミュレータの課題（第12回）で、「ブロックが見つからないまま線の終わりまで来たら、ブロックはあきらめてガレージに向かう」という機能を足すとします。上の10個の順番に当てはめると、何をどの順でやりますか。プログラムを書く前に、紙に書き出してください。そのあと、実際に作って、seed 1〜20 で確かめてください。
