第4回 Git で記録する

プログラムを直していると、「さっきまで動いていたのに、どこを変えたか分からない」ということが必ず起きます。Git は、ファイルの変更を記録しておいて、何を変えたかを見たり、前の状態に戻したりできる道具です。チームのプログラムと資料は、全部 Git で管理しています。

用意するもの：第2回で取ってきた ETrobo フォルダ

説明

Git がしてくれること

Git では、ファイルを変えたあと「ここまでを記録する」と決めた時点の状態を残していきます。この1つ1つの記録を「コミット」といいます。コミットには、何を変えたかの説明を書きます。

記録を残しておけば、昨日から何を変えたかを行ごとに見られます。壊してしまったら、記録した時点に戻せます。大会の前に「これで走った」という状態をコミットしておけば、当日何かあっても戻れます。

GitHub は、Git の記録をインターネット上に置いておく場所です。チームのみんなが同じ記録を共有できます。手元の記録を GitHub に送るのが push、GitHub の新しい記録を手元に取ってくるのが pull です。

ブランチ

行の頭の (main) は、今いる「ブランチ」の名前です。ブランチは、記録の枝分かれです。新しいことを試すときは別のブランチを作ってそこで作業し、うまくいったら main に合流させます。最初のうちは、先輩に言われたブランチで作業すれば大丈夫です。

よく使うコマンド

コマンド すること
git status 変えたファイルの一覧
git diff 何をどう変えたか（行ごと）
git add ファイル 次のコミットに入れる
git commit -m "説明" 記録する
git log --oneline 記録の一覧
git restore ファイル 最後に記録した状態に戻す（今の変更は消える）
git pull GitHub の新しい記録を取ってくる
git push 自分の記録を GitHub に送る

コミットの説明は、「何を、なぜ変えたか」を日本語で書きます。「修正」だけだと、あとで読んでも何のことか分かりません。

手順

この回は、練習用のフォルダの中だけで試します。最後に元に戻すので、チームの記録には何も残りません。

  1. ETrobo のフォルダに移って、今の状態を見る

    $ cd ~/Desktop/ETrobo
$ git status
$ git log --oneline | head -5

  2. 練習用のメモを1つ書き換える。VS Code で docs/後輩育成/練習/01_ターミナル/練習用データ/メモ/2026年/9月/0912_試走会.txt を開いて、最後に1行足して保存する

  3. 何が変わったかを見る

    $ git status
$ git diff

    足した行が、頭に + が付いて緑で出てきます

  4. 元に戻す

    $ git restore docs/後輩育成/練習/01_ターミナル/練習用データ/メモ/2026年/9月/0912_試走会.txt
$ git status

    VS Code で開き直すと、足した行が消えています

演習

演習4-1　消してしまったら

練習用のログを1つ、rm で消してください。そのあと、Git で元に戻してください。

答え 
$ rm docs/後輩育成/練習/01_ターミナル/練習用データ/logs/run_20261003_093000.log
$ git status
$ git restore docs/後輩育成/練習/01_ターミナル/練習用データ/logs/run_20261003_093000.log
コミットされているファイルなら、`rm` で消しても Git から戻せます。まだ一度もコミットしていないファイルは戻せません。

演習4-2　記録を読む

git log --oneline で、いちばん新しいコミットの説明を読んでください。git show --stat コミットの番号（番号は log の左の英数字）で、そのコミットで変わったファイルの一覧を見てください。

演習4-3　VS Code から見る

VS Code の左のアイコンの「ソース管理」（枝分かれのアイコン）を押すと、変えたファイルの一覧が出ます。演習4-1と同じことを、今度はファイルを書き換えてから、ソース管理の画面の「変更を破棄」で戻してみてください。コマンドと画面のどちらでも同じことができます。

次回までに

自分でコミットや push をするのは、先輩に言われてからで構いません。チームの記録に関わるので、最初の何回かは一緒にやります。
