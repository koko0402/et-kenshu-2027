第14回 状態機械図を描く

第12回で作ったシミュレータのプログラムを、状態機械図にします。描いたあと、図とプログラムが1対1で対応しているかを確かめます。後半は、本物のプログラムを題材にした穴埋めをします。

用意するもの：第12回の my_robot.c、draw.io（VS Code の Draw.io Integration か、ブラウザの https://app.diagrams.net ）

説明

なぜ図にするのか

プログラムが長くなると、どの状態からどの状態へ移るのかを、コードを読んで追うのは大変になります。図にすると、全体の流れが一目で分かります。抜けている移り変わり（たとえば「ブロックが見つからなかったらどうするか」）にも気づきやすくなります。

エントリークラスの規約には「ソースコード又はモデルは、…提出するモデルと全く関連のないものであってはならない」とあります（2.2）。モデルは提出のためにあとから描くものではなく、作る前に考えるためのもので、うまくいかなければモデルに戻って直します。

描き方

状態は角の丸い四角で描いて、中に名前を書きます。コードの enum と同じ名前にします。

移り変わりは矢印で描いて、矢印には [ ] で囲んで「何が起きたら移るか」を書きます。[超音波 < 300mm] や [334mm押した] のように、コードの if の条件がそのまま読めるように書きます。

状態の中には、その状態にいる間ずっとすることを do / で書きます。入ったときに1回だけすることは entry /、出るときに1回だけすることは exit / です。

最初の状態には黒い丸から矢印を引きます。終わりの状態からは二重丸へ矢印を引きます。

答えの例の状態機械図は、だいたいこうなります。

●→ ライントレース ─7250mm走った→ ゆっくりたどる ─超音波300mm以内→ 近づく ─当たった→ 押す
                                                                              │334mm押した
    線に乗る ←黒を見つけた─ ガレージの線を探す ←90度回った─ 右を向く ←200mm下がった─ 下がる
     │50mm進んだ
    左を向く ─90度回った→ 線をたどる ─線が切れた→ 入る ─200mm進んだ→ 終わり →◎

審査で何度も言われること

2026年の審査では、どのチームにも同じようなことが言われていました。描くときに気をつけてください。

一つ目は、手順の1つ1つを状態にしないことです。状態にするのは、制御のしかたが根本から切り替わる所です。たとえば「カメラで線をたどる」から「カラーセンサで縁をたどる」へ、「超音波で探す」へ、と変わる所です。手順を全部並べるなら、それはアクティビティ図です。

二つ目は、状態の名前です。「〜中」「〜へ遷移」のような名前は付けません。移り変わりは矢印で表すので、名前に「遷移」は要りません。

三つ目は、図の読みやすさです。2026年のうちのチームの図は、線が重なっていて文字が小さい、と指摘されました。線は重ねない、交差を減らす、左から右・上から下に読めるように置く、文字は印刷しても読める大きさ（12pt くらい）にする、を守ってください。

draw.io の使い方

左の図形の一覧の下の「その他の図形」から「UML」にチェックを入れると、状態機械図の部品が出てきます。図形を選んで Ctrl + D で複製、図形にマウスを乗せると出る青い矢印を引っ張ると線が引けます。複数の図形を選んで、右の「配置」で左揃えや等間隔にそろえられます。

画像にするときは「ファイル」→「エクスポート」→「PNG」です。

手順

  1. 第12回で書き出した状態の一覧を見ながら、まず紙に下書きする
  2. VS Code で新しいファイルを作り、名前を 状態機械図.drawio にして開く
  3. 状態を並べる。左から右、上から下へ流れるように置く
  4. 矢印を引いて、条件を書く
  5. 図とコードを並べて、矢印1本と if 1つが対応しているか、1つずつ確かめる

演習

演習14-1　自分の状態機械図

自分の my_robot.c の状態機械図を描いてください。描けたら、図とコードを見比べて、合っていなかった所を書き出してください。合っていない所があれば、図とコードのどちらかがおかしいということです。

演習14-2　抜けている移り変わりを探す

自分の図を見て、「こうなったらどうなる？」という場合を3つ考えてください。たとえば、ブロックが見つからないまま線の終わりまで来てしまったら、ガレージへの線が見つからないまま壁まで進んでしまったら、などです。今のプログラムでは、それぞれどうなりますか。シミュレータで確かめられるものは確かめてください。

演習14-3　本物の手順を状態にする

docs/後輩育成/練習/06_モデル図/練習_状態機械図.drawio を開いてください。2026年10月に作ったボトルの難所の手順（src/app_bottles.c）を題材にした、穴埋めの状態機械図です。

  1. 「？」の状態に名前と do / を書く
  2. 「色の判定」「押し出し」に do / を書く
  3. [　　] になっている移り変わりの条件を書く
  4. 右下のメモを「この図の要点」に書き換える（3行）

src/app_bottles.c の手順の番号は30近くありますが、状態は8つで足ります。手順と状態の違いを考えながら描いてください。
