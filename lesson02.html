第2回 開発環境とターミナル

自分のPCで、Cのプログラムを書いてコンパイルして動かせるようにします。後半は、これからずっと使うターミナルの基本を練習します。

用意するもの：自分のPC（Windows）、GitHub のアカウント

説明

ETロボコンの開発では、マウスでクリックするより、ターミナルで文字のコマンドを打つ場面のほうがずっと多くなります。ラズパイには画面をつながずに、PCから文字だけで操作するからです。

Windows では、ターミナルとして Git Bash を使います。Git for Windows と一緒に入るもので、ラズパイ（Linux）と同じ書き方でコマンドが打てます。Windows に最初から入っている PowerShell は書き方が少し違うので、この研修では使いません。

Cのコンパイラは gcc を使います。Windows では WinLibs というパッケージに gcc と mingw32-make（make の Windows 版）が一緒に入っています。

エディタは VS Code です。VS Code の下のほうにターミナルを出せるので、ファイルを書く画面とコマンドを打つ画面を1つの窓で使えます。

プログラムや資料は GitHub の非公開リポジトリに置いています。先輩に招待してもらってから取ってきます。

手順

入れる

  1. スタートメニューで「PowerShell」を開き、次の3行を1行ずつ打つ（終わるまで数分かかる）

    winget install Git.Git
winget install Microsoft.VisualStudioCode
winget install BrechtSanders.WinLibs.POSIX.UCRT

  2. PowerShell を閉じて、VS Code を開く

  3. VS Code の上のメニューで「ターミナル」→「新しいターミナル」を開き、右上の + の横の ∨ から「Git Bash」を選ぶ

  4. 次のように打って、3つとも版の番号が出ることを確かめる

    $ gcc --version
$ mingw32-make --version
$ git --version

    command not found と出るものがあったら、VS Code を一度閉じて開き直してからもう一度打つ。それでもだめなら先輩に言う

プロジェクトを取ってくる

  1. 先輩に GitHub のアカウント名を伝えて、リポジトリに招待してもらう。メールで来る招待を承認する

  2. Git Bash で、取ってくる

    $ cd ~/Desktop
$ git clone https://github.com/koko0402/et-koko.git ETrobo
$ cd ETrobo

    初めてのときは GitHub へのログインの画面が出るので、ブラウザでログインする

  3. VS Code の「ファイル」→「フォルダーを開く」で Desktop/ETrobo を開く

ターミナルの基本

ターミナルの行の頭はこうなっています。

taro@PC MINGW64 ~/Desktop/ETrobo (main)
$

taro@PC が誰がどのPCで、~/Desktop/ETrobo が今いるフォルダ、(main) は Git のブランチの名前です。$ は「ここに打ってください」という印なので、$ 自体は打ちません。

よく使うコマンドはこれくらいです。

$ pwd                 # 今いるフォルダを表示
$ ls                  # フォルダの中身を一覧
$ cd docs             # docs フォルダに入る
$ cd ..               # 1つ上に戻る
$ cat README.md       # ファイルの中身を表示
$ grep LAP README.md  # LAP を含む行だけ表示

キーは、Tab（ファイル名の続きを補ってくれる）、↑（前に打ったコマンドを呼び出す）、Ctrl + C（動いているものを止める）の3つを覚えておけば困りません。特に Tab は打ち間違いが減るので、どんどん使ってください。

もっと詳しいことは、去年の資料の docs/後輩育成/02_ターミナルとラズパイ.md と docs/後輩育成/コマンド早見表.md にあります。

演習

演習2-1　フォルダの中を歩く

ETrobo から cd だけで docs/後輩育成/新人研修2027/ドリル まで移動して、ls で中身を表示してください。移動できたら pwd で場所を確かめて、cd ~/Desktop/ETrobo で戻ります。日本語のフォルダ名は、最初の1文字を打って Tab を押すと補ってくれます。

演習2-2　初めてのコンパイル

ドリル フォルダで sh check.sh を打ってください。まだ何も書いていないので「合格 0 / 12 問」と出れば、gcc もドリルも正しく動いています。

うまくいかないとき `gcc: command not found` なら、手順の「入れる」の4に戻る。`No such file or directory` なら、今いるフォルダが違うので `pwd` で確かめる。

演習2-3　探す

src フォルダの中で、PID という文字が出てくるファイルを探してください（ヒント：grep -r PID src）。いくつのファイルが出てきましたか。それぞれのファイルが何をするものか、ファイル名から想像してみてください。
