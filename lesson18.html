第18回 ログを読む・Python で集計する

走行体は、走りながら「何を見て、どう判断したか」を1行ずつログに書いています。うまく走らなかったとき、原因を探す手がかりはログしかありません。この回は、ログの読み方と、何本ものログをまとめて比べる Python のスクリプトの書き方をやります。

用意するもの：前の回で持ってきたログ（無ければ練習用のログ）

説明

ログの読み方

ログには、1秒ごとの状態の行と、判断したときのメッセージの行があります。

[ 12.0s] 前半走行 入力=カメラ ライン=検出 offset=+0.05 … 位置=(x,y) 走行距離=…
LAPゲート到達と判断(青線検知)

1秒ごとの行は [ で始まります。第3回でやった grep -v "^\[" でこれを除くと、判断のメッセージだけが残って読みやすくなります。

よく見るメッセージは次のとおりです。ライン逸脱を検知しました は線を見失ったという意味で、直前の offset と場所を見ます。LAPゲート到達と判断(青線検知) は青い線を見て判断した、(オドメトリ距離(保険)) が付いていたら、青が見えないまま距離で判断した、という意味です。「見えないまま◯mm進みました」のような行が多い走りは、うまくいっていても危ない走りです。駆動輪のストールが続いたため は、何かに押し付けて車輪が回っていない、という意味です。

気をつけてほしいのは、ログに書かれているのは「走行体がそう判断した」ことで、本当にそうだったかは分からない、ということです。走行体が「ガレージに着いた」と書いていても、道を間違えて別の場所で止まっていることがあります。

Python

Python は、C と違ってコンパイルせずにすぐ動かせる言語です。2026年のプログラムでは、カメラの画像処理（src/recognition/vision_server.py）と、補助のスクリプト（scripts/）を Python で書いていました。ログを集計するような、ちょっとした道具を作るのに向いています。

speed = 70                    # 型は書かなくていい
if speed > 50:
    print("速い")             # 行の頭の空白で、if の中だということを表す
for i in range(3):            # 0, 1, 2
    print(f"{i + 1}回目")     # f"..." の中の {} に値が入る

C との大きな違いは、{ } の代わりに行の頭の空白（インデント）で範囲を表すことです。空白の数がそろっていないと IndentationError になります。

ファイルを1行ずつ読むのは、こう書きます。

with open("logs/run_20261003_101500.log", encoding="utf-8") as f:
    for line in f:
        if "LAPゲート到達" in line:
            print(line.strip())

ログを集計するスクリプトは、たいていこの形で書けます。

手順

Python を入れる

  1. PowerShell で winget install Python.Python.3.13 を打つ
  2. VS Code を開き直して、Git Bash で python --version と打ち、版の番号が出ることを確かめる

集計のスクリプトを動かす

  1. 練習のフォルダに入って、動かす

    $ cd ~/Desktop/ETrobo/docs/後輩育成/練習/03_Python
$ python ログ集計.py

    まだ中身を書いていないので、- や 0 ばかりの表が出ます

  2. ログ集計.py を開いて、「ここを書く(1)(2)」を埋める

演習

演習18-1　集計を完成させる

ログ集計.py を完成させてください。次の表が出れば完成です。

ログ                          LAP[秒]   QR ガレージ(本人談)   予定外    最大ずれ
run_20261003_093000.log          -    8       着いた     1    0.98
run_20261003_110000.log          -   10       着いた     3    0.98
run_20261004_101500.log          2    0       着いた     0    0.99

答えは同じフォルダの 答え/ログ集計.py にあります。

演習18-2　表を読む

  1. 上の2本は LAP が - です。なぜでしょう（ログの最初の数行を見る）
  2. run_20261003_110000.log は「ガレージ(本人談)」が「着いた」なのに、第3回の演習3-5では失敗した走行でした。どういうことでしょう
  3. 「最大ずれ」がどれも1に近いのはなぜでしょう
答え 1. この2本は難所側の線の上から始める確認用の走り方（`--from-nansho`）なので、前半もLAPも通らない。 2. ログに書かれるのは走行体がそう判断したことで、本当にガレージの中にいるかは分からない。110000 は道を間違えたまま「ここがガレージのはず」と止まっている。 3. 線を見失っている間（難所で線の無い所を走っている間）も、最後に見た offset の値が残って出ているため。`ライン=検出` の行だけに絞ると、ボトルの走り（101500）は0.51まで下がる。

演習18-3　列を足す

次のどれかの列を足してください。ボトルの色（「ボトルの色は黄です」の行から色を取り出す）、最後の行の時刻（何秒で終わったか）、「ライン逸脱を検知」の回数。

演習18-4　自分のログで

前の回で持ってきた自分のログを python ログ集計.py 自分のログのファイル で集計してください。
