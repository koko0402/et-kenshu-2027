第10回 AIとの付き合い方

2026年のチームは、プログラムや設計書、資料の多くを、生成AI（VS Code の中で動く Claude Code）と一緒に作りました。うまく使えば作業はずっと速くなりますが、AIの言うことをそのまま信じて時間を失ったこともありました。この回では、そのときに分かったことと、チームの決まりごとを話して、実際にシミュレータの課題をAIに相談しながらやってみます。

用意するもの：第7回の my_robot.c、生成AIのサービス（チームで使っているもの）

説明

生成AIは何をしているか

ChatGPT、Claude、Gemini などの生成AIは、大量の文章とコードから学んで、「この続きとしてもっともらしいもの」を作ります。

だから、よくある書き方のコード（PID や状態機械）を書いたり、エラーメッセージの意味を説明したり、長いログから変わった所を探したりするのは得意です。

一方で、AIは実機を見ていません。センサの値やモータの癖は、こちらが教えない限り知りません。知らないことでも、もっともらしく答えることがあります（存在しない関数を書いたりします）。毎年変わる規約を正しく知っているとも限りません。それから、「動くはず」と「動いた」の区別がつきません。

2026年にあったこと

実機の走りがずれた瞬間に止まったことがありました。実は人がハブの電源を手で切っていたのですが、ログしか見ていないAIは「ハードの故障」と考えました。AIに渡す情報が足りないと、間違った結論を出します。

ハブとの通信の処理をAIと一緒に自分たちで書いたときは、不具合を8件踏んで、最後は公式のライブラリに戻しました（docs/設計/判断記録.md 2026-09-10）。公式に用意されている部品があるなら、まずそれを使うべきでした。

ETラリーのゲートの位置が変わるルールにも、人もAIも早く気づけませんでした。規約は、AIの要約ではなく人が原文で読みます。

逆にうまくいったのは、仮想コースで条件を変えて何百回も走らせて集計する作業です。こういう、やることがはっきりしていて結果を数字で確かめられる作業は、AIに任せると速いです。

どのファイルのどこの話か、今どうなっていてどうしたいか（数字で）、自分が見たこと、守ってほしい決まりを書いて、理由も出してもらいます。それから、一度に大きく変えさせないことです。1つ変えて、ビルドして、走らせて、次へ進みます。

このプロジェクトでは、AIに毎回読ませる決まりを CLAUDE.md（いちばん上のフォルダ）に書いてあります。一度読んでおいてください。

チームの決まりごと

AIが書いたコードは、自分で1行ずつ説明できるようになるまでコミットしません。ビルドして、シミュレータと実機で確かめるまでは「できた」と言いません。

パスワードや ssh の鍵、メンバーの名前やメールアドレスは貼りません。参加者だけに配られた資料は、許可なく外に出すことが禁止されているので（参加規約 8.(9)）、外部のAIサービスに貼る前に先輩に相談してください。

モデル図や提出資料も、AIに手伝ってもらうのは構いませんが、中身を決めるのはチームです。審査で説明するのは自分たちです。AIが公開されているコードとそっくりのものを出してきたときは、そのライセンスに従います（参加規約 8.(1)）。

2026年度の規約には、生成AIの使用を禁止したり制限したりする書き方は見当たりませんでした。ただ毎年変わるので、2027年度の規約が出たら確かめてください。

走行体の中の「AI」

アプライドクラスではカメラの画像から線や色、QRコードを見つけます。2026年のチームは機械学習を使わず、OpenCV で「暗い所を探す」「色の範囲で切り出す」といった決まった処理で作りました（src/recognition/vision_server.py）。学習用の画像を集める時間が無かったことと、なぜそう判定したかを説明しやすいことが理由です。機械学習を使うと照明の変化に強くできるかもしれませんが、学習データを集める手間や、ラズパイで間に合う速さにする工夫が要ります。来年やってみたい人は、まず今の方法で何が見分けられなかったかを、ログと画像で集めるところから始めてください。

手順

  1. 自分の my_robot.c で、うまくいっていない所を1つ決める（なければ、seed を11〜50に広げて、ガレージに入れない seed を探す）
  2. その seed で走らせて再生し、どの状態で何が起きたかをメモする
  3. 上の「良い例」の形で、AIに相談する
  4. 返ってきた提案を読んで、理由が納得できる所だけ取り入れる
  5. 走らせて確かめる。良くならなければ、メモに戻って何が足りなかったか考える
  6. 何を聞いて、何を採用して、何を採用しなかったかを my_robot.c の先頭のコメントに残す

演習

演習10-1　説明させて確かめる

src/localization/odometry_math.c をAIに説明させてください。説明に出てきた式を、ドリル問題7の自分の答えと見比べて、合っているか自分で確かめます。違う所があったら、どちらが正しいかをコードで確かめてください。

演習10-2　頼み方を比べる

第6回の演習6-3（PDで速くする）を、上の悪い例と良い例の2通りで頼んでみてください。出てきたものを比べて、良い例のほうが良かった点を3つ書いてください。

演習10-3　速さと確実さ

前半の速さを70、80、90、100と変えて、それぞれ seed 1〜50 を走らせ、平均の点数とガレージまで行けた回数を表にしてください。集計のスクリプトをAIに書いてもらってもいいですが、出てきた数字が正しいかは、何本かの seed を自分で走らせて確かめてください。
