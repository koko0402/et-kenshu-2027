第17回 走行体のプログラムを動かす（実習）

前の回でラズパイに送った、2026年の本物の走行体のプログラムを動かします。コマンドを打つと中で何が起きているのか、うまくいかないときに何が出るのかも合わせて覚えます。

用意するもの：前の回でセットアップした走行体、練習用のコース（無ければ白い紙に黒いテープを貼る）

説明

どこで何を打つか

この回は、PCで打つコマンドと、ラズパイの中で打つコマンドが混ざります。行の頭が自分のPCの名前ならPC、pi@etrobo ならラズパイです。

  PC                                        ラズパイ
  プログラムを書く       ── deploy.sh で送る ──▶  make pi（ビルド）
  シミュレータで試す                           make camera（カメラ確認）
                         ── ssh で操作する ──▶  make start（走らせる）
  ログを読む            ◀── scp でログを取る ──   logs/run_日時.log

送ってビルドする（PCで）

プログラムを直したら、毎回 PC から送ります。

$ sh scripts/deploy.sh pi@etrobo.local

中では、プログラム一式を送り、ラズパイに足りないソフトがあれば入れ、ラズパイの上でビルドして、最後に sync で書き込みを終わらせています。最後に「== 完了。」と出れば成功です。

ビルドの途中で error: が出て「完了」が出なかったときは、ラズパイの上のプログラムは古いままです。そのまま走らせると、直す前の動きをします。

走らせる（ラズパイで）

pi@etrobo:~/etrobo $ make start OPT="--line-trace-only --speed 20"

いちばん使うコマンドです。打つ前に、ハブの電源を完全に切って入れ直します。

中では、まずカメラのプログラム（src/recognition/vision_server.py）を裏で起動して、準備ができるのを待ってから、走行体の本体（build/etrobo）を起動します。画面に出る文字は、全部 logs/run_日時.log にも保存されます。Ctrl + C で止めると、カメラのプログラムも一緒に止まります。

OPT="..." には、本体に渡すオプションを書きます。

オプション すること
--line-trace-only --speed 20 難所に移らず、遅くライントレースだけ（初めて走らせるとき）
--stop-at-lap LAPで止まる（前半だけ確かめる）
--skip-obstacles LAPのあと難所に行かずガレージへ（完走だけ確かめる）
--lap-left スタートから通し（2026年の本番）
--no-calibration 黒と白を測るのを省く（練習で何本も走らせるとき。本番では使わない）
--help 全部のオプションの説明

正常なときに出るもの

ハブとつながると SPIKE asp.bin version=... と出ます。次に「黒の上に置いて」「白の上に置いて」と出るので、走行体をそこに置いて、1秒止めてからフォースセンサ（押しボタン）を押します。これがキャリブレーションで、「目標輝度を確定しました」と出ます。「スタート合図を待っています」と出たら、もう一度フォースセンサを押すと走り出します。

走っている間は、1秒ごとに [ 12.0s] 前半走行 入力=カメラ ライン=検出 offset=+0.05 … のような行が出ます。offset は線のずれで、−1が左、+1が右です。最後に「競技終了。」と出たら終わりです。

うまくいかないとき

port =A getdevice time out は、ハブが固まっています。ケーブルではありません。ハブの電源を切って5秒待ってから入れ直して、やり直します。

SPIKE version mismatched! は、ハブのファームウェアの版とプログラムの版が違います。make pi SPIKE_VERSION=0.1.1 のように、その台に合わせてビルドし直します。

vision_server.py が起動しませんでした は、カメラが無いか、前に走らせたプログラムがカメラを掴んだまま残っています。次のコマンドで、残っているものを探して止めます。

pi@etrobo:~/etrobo $ pgrep -af "[e]trobo /dev|[v]ision_server"
pi@etrobo:~/etrobo $ pkill -f "[e]trobo /dev"; pkill -f "[v]ision_server"

名前の最初の1文字を [ ] で囲んでいるのは、コマンドの行そのものに一致して自分を止めてしまわないようにするためです。

カメラの向きを確かめる

pi@etrobo:~/etrobo $ make camera SHOT=1

本番と同じ方法で黒い線を探して、「良好」「面積比 0.12」のように出します。モータは動きません。走行体のすぐ前の床と黒い線が写っていて、機体の部品が写っていなくて、面積比が0.10〜0.20くらいなら大丈夫です。どこかにぶつけたあとは、カメラの向きがずれていることが多いので、必ず確かめます。

make camera VIEW=1 にすると、PCのブラウザで http://etrobo.local:8080/ を開いてカメラの映像を見ながら合わせられます。

ssh が切れても止まらないように

ssh が切れると、そこで動かしていたプログラムも止まります。大会では切れても走り続けるように、こう起動していました。

pi@etrobo:~/etrobo $ setsid nohup sh scripts/wait_and_run.sh "--lap-left" > /tmp/run_console.log 2>&1 &
pi@etrobo:~/etrobo $ tail -f /tmp/run_console.log

wait_and_run.sh は、ハブの電源が入れ直されるのを見張っていて、入れ直されたら8秒待って make start します。ハブの電源を入れ直すだけで走らせられるので、本番で慌てずに済みます。

会場には Wi-Fi が無いことがあります。そのときはラズパイ自身を Wi-Fi の親機にして、PCをそこにつなぎます。やり方は scripts/pi_access_point.sh の先頭のコメントにあります。学校の Wi-Fi があるうちに一度試しておいてください。

手順

  1. PCから送る（sh scripts/deploy.sh pi@etrobo.local）。「== 完了。」が出るのを確かめる
  2. ラズパイに ssh で入って、cd ~/etrobo
  3. make camera SHOT=1 でカメラの向きを確かめる
  4. make check で点検する（車輪を浮かせて）
  5. ハブの電源を切って入れ直す
  6. make start OPT="--line-trace-only --speed 20" で走らせる。黒、白の順にキャリブレーションして、スタート
  7. Ctrl + C で止めて、ハブの電源を切る
  8. PCにログを持ってくる（PCで scp pi@etrobo.local:etrobo/logs/run_*.log .）

演習

演習17-1　1本走らせる

手順どおりに1本走らせて、ログをPCに持ってきてください。ログの最初の10行と、最後の5行を表示してください。

演習17-2　速さを変える

--speed 20 を 30、40 と変えて走らせてください。どこから線を外れるようになりましたか。ログの offset の値はどう変わりましたか。

演習17-3　わざと失敗する

ハブの電源を入れ直さずに、2回続けて make start してください。何が出ますか。そのあと正しい手順で走らせ直してください。

答え `getdevice time out` や「ハブが応答しません」が出る。ハブは電源を入れるたびに1回しか接続を受け付けないので、毎回入れ直す。
