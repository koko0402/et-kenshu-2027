第8回 状態機械図を描く

前回作った走行体のプログラムを、モデル（状態機械図）にします。ETロボコンではモデルも審査されるので、ここからモデルの描き方に入っていきます。

用意するもの：前回の my_robot.c、draw.io（VS Code の拡張「Draw.io Integration」か、ブラウザ版）

説明

なぜ図にするのか

プログラムが長くなると、どの状態からどの状態へ移るのかを、コードを読んで追うのは大変になります。図にすると、全体の流れが一目で分かります。抜けている移り変わり（たとえば「ブロックが見つからなかったらどうするか」）にも気づきやすくなります。

ETロボコンでは、プログラムとモデルが対応していることが求められています。エントリークラスの規約には「ソースコード又はモデルは、…提出するモデルと全く関連のないものであってはならない」とあります（2.2）。モデルは提出のためにあとから描くものではなく、作る前に考えるためのもので、うまくいかなければモデルに戻って直します。

状態機械図の描き方

状態は角の丸い四角で描いて、中に名前を書きます。コードの enum と同じ名前にします。

移り変わりは矢印で描いて、矢印には「何が起きたら移るか」を書きます。超音波 < 300mm や 334mm押した のように、コードの if の条件がそのまま読めるように書きます。

最初の状態には、黒い丸から矢印を引きます。終わりの状態には、二重丸へ矢印を引きます。

答えの例の状態機械図はこうなります（スライドにも載せています）。

●→ ライントレース ─7250mm走った→ ゆっくりたどる ─超音波300mm以内→ 近づく ─当たった→ 押す
                                                                              │334mm押した
    線に乗る ←黒を見つけた─ ガレージの線を探す ←90度回った─ 右を向く ←200mm下がった─ 下がる
     │50mm進んだ
    左を向く ─90度回った→ 線をたどる ─線が切れた→ 入る ─200mm進んだ→ 終わり →◎

審査員に見られるところ

2026年の講評では、うちのチームの図は線が重なっていて文字が小さい、と指摘されました。評価が高かったチームは、目標の点数と時間を理由をつけて決めて、それを図の中で説明していました。

モデルの詳しい描き方は、去年の資料の docs/後輩育成/05_モデル図の読み方と作り方.md にあります。2026年の各チームの提出モデルと講評はプロジェクトの docs/手がかり/モデルの参考/ にあるので、いちばん評価が高かったチームのものを一度見てみてください（どれかは先輩に聞いてください）。

手順

  1. 前回書き出した状態の一覧を見ながら、紙に状態機械図を下書きする
  2. VS Code で 新規ファイル を作り、名前を 状態機械図.drawio にして開く（Draw.io Integration が入っていれば、そのまま描ける）
  3. 状態を並べる。左から右、上から下へ流れるように置くと、線が交差しにくい
  4. 矢印を引いて、条件を書く
  5. 図とコードを並べて、矢印1本と if 1つが対応しているか、1つずつ確かめる

演習

演習8-1　自分の状態機械図

自分の my_robot.c の状態機械図を描いてください。描けたら、図とコードを見比べて、合っていなかった所を書き出してください。合っていない所があれば、図とコードのどちらかがおかしいということです。

演習8-2　抜けている移り変わりを探す

自分の図を見て、「こうなったらどうなる？」という場合を3つ考えてください。たとえば、ブロックが見つからないまま線の終わりまで来てしまったら、ガレージへの線が見つからないまま壁まで進んでしまったら、などです。今のプログラムでは、それぞれどうなりますか。シミュレータで確かめられるものは確かめてください。

演習8-3　去年の練習

去年の資料の docs/後輩育成/練習/06_モデル図/ に、状態機械図の穴埋めの練習があります。やってみてください。
