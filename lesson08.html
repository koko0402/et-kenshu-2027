第8回 C言語 PID制御と状態機械

走行体のプログラムの中心になる2つ、PID制御と状態機械を書きます。ドリルの問題9〜12をやります。ここで書いたものは、第11回からシミュレータでそのまま使います。

用意するもの：第7回のドリルの続き

説明

PID制御

ライントレースでは、カラーセンサで線の縁を見て、明るすぎたら線のほうへ、暗すぎたら線の外へ曲がります。どれだけ曲がるかを決める方法の一つが PID制御です。

ずれ（error）を「今の明るさ − 目標の明るさ」とすると、

P = KP × 今のずれ
I = KI × これまでのずれの合計
D = KD × （今のずれ − 前回のずれ）
曲がる量 = P + I + D

P は今どれだけずれているか、I はずれがどれだけたまっているか、D はずれがどれだけ速く変わっているかを見ています。ライントレースでは I はあまり使わず、P と D で走ることが多いです。どの値がどう効くかは、第10回と第11回で実際に動かして見ます。

D を計算するには前回のずれが要るので、それを構造体に覚えておきます（第7回の「前の値を覚えておく」と同じです）。

状態機械

走行体は、区間によってやることが変わります。線をたどる、ブロックに近づく、押す、下がる、回る……。今どれをやっているかを「状態」として持っておいて、何かが起きたら次の状態に移る、という作り方を状態機械といいます。

C では enum で状態に名前を付けて、switch で切り替えます。

typedef enum { ST_IDLE, ST_RUNNING, ST_STOPPED } State;

switch (state) {
case ST_IDLE:
    if (button_pressed) state = ST_RUNNING;
    break;
case ST_RUNNING:
    if (goal_reached) state = ST_STOPPED;
    break;
...
}

モデル図の状態機械図と、このコードはそのまま対応します。図の矢印1本が、case の中の if 1つです。モデル審査で「モデルとコードが対応しているか」を見られるのは、こういうところです。

見間違いを防ぐ

センサやカメラは、一瞬だけ違う値を出すことがあります。2026年は青い印を一瞬見間違えて、早く曲がってしまうことがありました。「何回か続けて見えたら本物とみなす」ようにすると防げます。問題11がその練習です。
